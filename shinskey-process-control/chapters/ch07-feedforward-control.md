# Chapter 7: Feedforward Control

## Core Idea
Feedback has three structural failings on a difficult process: it needs a measurable error before it can act (so the error must be integrated out, and IE = P·I/100 per unit load change, which is exactly what makes hard processes disturbance-sensitive); it solves the control problem by trial and error; and it has a natural period, so disturbances arriving more often than about every three periods never let it settle. Feedforward replaces trial and error with a **model of the process**: measure the load, compute the correct manipulated variable from material and energy balances, and act before the disturbance reaches the controlled variable. It is capable of perfect control, limited only by measurement and model accuracy — and, crucially, the controlled variable need not be measured at all.

## Frameworks Introduced
- **The controller as a process model**: the model reverses the process — solve for the manipulated variables in terms of the loads, and substitute **set points for the controlled variables**. It must contain both a steady-state part (otherwise offset, possibly load-dependent) and a dynamic part (otherwise a transient whenever the load changes, lasting until new energy levels are established). Perfect steady state + perfect dynamics = no measurable deviation at any time.
- **Integrals of flow (level, pressure) give linear calculations**: τ·dc/dt + c = m·Km·gm − q·Kq·gq (7.1), and with dr/dt = 0 the solution is **m = (Km·r + Kq·q)/(Km·gm)... i.e. m = r + (Kq/Km)q** (7.2) — the set point is *added*, so it contributes little to the loop; the load is what matters.
  - Drum-boiler feedwater: WF = Ws + (mL − 0.5)·(scale) — feedwater set point = steam flow plus a level-controller trim whose normal output is 0.5. Two advantages: feedwater flow never moves faster or farther than steam flow, and level control no longer depends on a tightly tuned feedback controller. The level controller's output bias must be 0.5 so it operates mid-scale. Level is non-self-regulating, so a PI controller is mandatory; with a forward loop in service the controller only has to trim the computation error, not integrate the whole load change.
  - **Windup protection by back-calculation**: solve the same equation in reverse with measured WF and the feedback signal fL substituted — fL = 0.5 + (WF − Ws)/K. Zero flow deviation ⇒ fL = mL ⇒ normal integration; any flow-controller deviation ⇒ the level controller degrades to proportional without winding up.
- **Averaging level control (the opposite objective)**: keep manipulated flow as constant as possible while level stays in bounds. Proportional-lag control (feedforward through a first-order lag τf plus a proportional level controller) returns level to set point with an offset equal to the flowmeter error divided by controller gain; it is implementable on a PI controller by replacing the integral feedback with the measured load, with I becoming the feedforward lag. Response is a lead plus two lags (τf and τv·PL/100), so outflow always overshoots inflow before settling — but proportional-lag control rises *faster* than plain proportional control unless the band is widened considerably. **A ramp beats a lag**: same maximum-rate equations, but the same integrated difference with less overshoot, or twice the ramp time for the same overshoot (Ref. 2's "optimal averaging level control").
- **Properties of a stream (temperature, composition) give nonlinear calculations**: c = Kp·m·gm/(q·gq) (7.6), so **m = r·q·(gq/gm)/Kp** (7.7) — load and set point are *multiplied*, so the set point contributes as much as the load, and the compensator is a ratio gq/gm.
- **Heat exchanger, the canonical case**: Q = Ws·Hs = Wp·Cp(T* − Ti) → **Ws = Wp·K(T* − Ti)**, multiplication of flow by temperature, with K (combining Cp/Hs and meter scaling) as the single calibrating adjustment (subtractor gain). Two failings: a dynamic imbalance after every load change, and offset at loads other than the calibration point. One large virtue: **it fails safe** — lose process flow and steam flow automatically stops, where feedback would drive steam wide open because the outlet measurement no longer responds. Write the model from mass and energy balances: they are the easiest equations to write, contain the fewest unknowns, do not change with time, and — the point worth internalizing — you do not need the heat-transfer coefficient, the area, or the tube gradient. Fouling changes the valve position required, not the steam flow demanded.
- **Ratio control is feedforward**: when the true controlled variable is the ratio R = f/q or q/f (7.8) and it may not be measurable, the obvious implementation puts a **divider inside the feedback loop** — either loop gain varies with the wild variable, or the loop becomes nonlinear (dR/df = 1/q, dR/df = q/f² = R/f) (7.9). Move the division to the **set-point circuit**: r = R·q. The wild variable is multiplied by an adjustable coefficient in a **ratio station** (gain range typically 0.3–3.0, midscale 1.0, assuming meters sized so all read similar percentages). With differential meters the transmitted variable is flow *squared*, so the ratio setting is the square root of the gain. If the ratio is to be set by a controller (composition in a blend), a multiplier is used, and its gain dR relation to the wild flow makes **gain vary directly with flow — much preferable to inverse variation**, which is what the in-loop divider gives.
- **Digital blending**: turbine, positive-displacement and vortex meters emit pulses proportional to volume. A set-point pulse train (from a master oscillator) increments an up-down counter while measurement pulses decrement it; the residual count is the volume error, and driving a valve proportionally to it is **integral control of flow rate** with time constant related to the volume error V for 100% output (7.10–7.11). The defect: **volume offset** — after a rate change, the rate error is eventually zero but the area between demand and delivery curves leaves a standing volume error EF = m·V (7.12), which matters in small batches (hundreds of counts) and not in continuous flow (thousands). Cure: a **second integral** (volume error acted on by PI, 7.13–7.14) — double integral alone is unstable (180° at all periods), but PI on top of it is stable. Cost: the volume controller adds ~100° of lag, roughly doubling the loop period (volume loops cycle at 2–20 s vs 1–10 s for flow), and the two integrations plus any valve dead band will limit-cycle — which is why a valve positioner, normally wrong on flow, is acceptable here (the periods are far apart). A **pacing loop** protects blend composition: a valve-position controller on the most-open valve (via high selector) overrides the master demand, sacrificing production rate to keep the blend uniform; set the VPC at ~95% stroke to make it always limiting when production is to be maximised.
- **Why dynamic compensation is needed**: raising the rate of energy transfer requires first raising the *energy level* of the process (the heat exchanger shell must hold more steam before it can transfer more). Without extra steam deliberately added, the level is raised by *temporarily withdrawing less* energy — hence outlet temperature dips on a load increase. The feedforward controller needs only the **ratio gq/gm**, never gm·gp, so where load and manipulated variable enter at the same place (a blending vessel) there may be no dynamic requirement at all.
- **Dead-time-only imbalance, exactly**: with dead times τdm and τdq, the closed-loop incremental response is **dc(t) = dr(t − τdm) + (dq·r/q)(τdq − τdm)** (7.18) — a set-point lag of τdm, and a **load transient of duration τdq − τdm and magnitude r·dq/q**. A time advance is impossible, so compensation means delaying the feedforward signal by τdq − τdm; **if τdm > τdq, compensation is impossible.**
- **Nine process classes (Fig. 7.18)**: dead time on the manipulated side can be less than, equal to, or greater than on the load side, and the same for capacity. Class I needs no dynamic compensation when its dead times are balanced (Ib is fully balanced); class Ia/Ic produce a rounded peak (Eq. 7.19), class II becomes class I once dead-time compensation is applied, and **class III cannot be balanced at all** because the manipulated side's dead time is too long. Peak time and height: for classes I/IIa/IIIc, t_p = ln(τq/τm)/(1/τm − 1/τq) + (τdq/τq − τdm/τm) (7.20) and c_p − r = (Δq·r/q)(e^(−(t_p−τdq)/τq) − e^(−(t_p−τdm)/τm)) (7.21); for the rest the peak is pointed and occurs when the longer dead time elapses (7.22–7.24). Classes IIc and IIIa cross set point before settling (7.25–7.26).
- **Uncompensated IE is a simple parameter sum**: **IE = −Δq·(r/q)(τm + τdm − τq − τdq)** (7.27) — note that IE can be zero while the process is still dynamically imbalanced (classes IIc, IIIa). Adding the compensator's own area (τ1 − τ2 for a lead-lag, Eq. 7.33) gives the tuning target: **IE = −Δq(r/q)(τm + τdm − τq − τdq − τ1 + τ2 + τd)** (7.34).

## Key Concepts
- **Dynamic compensators**: a **digital dead-time unit** is an array y(N) with N = τd/Δt shifted one position per sample (7.28); note that changing τd at runtime requires changing the sample interval, not N. The **lead-lag unit** (7.29) has instantaneous gain τ1/τ2 and recovers 63% of steady state in τ2, and can be tuned to overshoot, undershoot, or momentarily reverse (τ1 < 0 — a negative lead, which shifts phase 0 to −180° with no attenuation and, in a feedback loop, behaves much like dead time). Its digital forms: z = x + (x − y)(τ1 − τ2)/(Δt + τ2) (7.30) and y = y + (x − y)·Δt/(Δt + τ2) (7.31); practical instantaneous gain is (Δt + τ1)/(Δt + τ2). A lead-lag can also be built from a PI controller with the signal as set point and its own output as the controlled variable — output leads by I and lags by (100/P)-augmented time (7.32) — with a repeat-cycle timer to stretch time constants arbitrarily, and manual transfer to hold the last output on signal failure (valuable for analyzers).
- **Tuning dynamic compensators, in order**: (1) apply dead-time compensation τd = τdq − τdm where possible; (2) drive **IE to zero** by adjusting τ1 and τ2 — that fixes the *difference* τ1 − τ2; (3) then adjust the **ratio τ1/τ2** (keeping the difference) to minimise IAE. If the residual deviation sits on the load side of set point, τ1 > τ2; if it is still in the same direction, raise the ratio by reducing both, otherwise raise both. Minimum IAE usually coincides with IE = 0, though classes IIIb and IIIc may not reach zero.
- **Table 7.1 — compensator settings by class** (τd column is the dead-time compensation used; the lead/lag columns are for use *without* dead-time compensation): class I — τd not required, τ1 = τm, τ2 = τq; class II — τd = τdq − τdm, then τ1 = τm, τ2 = τq; **IIa** (no dead-time compensation) — τ1 = τm − ... with the negative-lead approximation, required when τm < 1.4(τdq − τdm); **IIb** — τ1 = −(τdq − τdm)/2, τ2 = half of that (negative lead approximating dead time); **IIc** — τ1 = τm − τdm, τ2 = τq − τdq; **IIIa** — τ1 = τm − τdm, τ2 = τq − τdq; **IIIb** — τ1 = ½(τdm − τdq), τ2 = τ1/10; **IIIc** — τ1 = 0.8τm + 0.4(τdm − τdq), τ2 = τq + 0.2τm + 0.6(τdm − τdq). For all, τ2 ≥ τ1/10, and the lead-lag ratio is capped at 10 for the same reason derivative gain is limited.
- **Class III results**: compensation is only effective after the dead time has elapsed, but it still cuts IAE by a factor of **3 to 5**; peak error improves only in class IIIc. High lead-lag ratios saturate on a large (20%) step and destroy the area balance — smaller steps balance better. Feedforward with lead-lag typically reduces IAE by **10× or more** versus feedback on the same loop (heat-exchanger record, Fig. 7.21).
- **Adding feedback is about accuracy, not speed**: feedback's only job is to remove the offset left by measurement error, calculation error, model inadequacy (mass/heat-transfer coefficients over a wide range), and excluded load components (heat loss, ambient). **Trim the set point** of the feedforward system, not the coefficient K — the set point is already scaled in the controlled variable, and it is the only single knob that catches whichever error dominates. Benefits of that placement: startup in manual is unambiguous (set the controller output equal to its set point), and the controller's output *is* a readout of the forward loop's error, so controller output vs load can identify the model's weak term. Offset from a manipulated-variable error varies inversely with load: dc = Kp·(dm/q).
- **Integral is normally the only useful feedback mode** because feedforward is justified precisely on hard, demanding loops: P and D respond too slowly to contribute to load response and can destabilise an otherwise stable system, so relax whatever you do use. For a non-self-regulating process (level), proportional action is nonetheless essential.
- **Never put the dynamic compensator inside the feedback path** — with a lead-lag between controller output and the manipulated variable, an operator's manual adjustment can take minutes or an hour to appear, making manual operation impossible. Each forward loop ideally gets its own compensator, but only flow inputs change fast enough to warrant one.
- **Windup protection with two forward inputs**: back-calculation gets complicated, so instead **add the secondary controller's deviation to the primary output for integral feedback** — at zero deviation the primary sees its own output and integrates normally; if the secondary measurement fails to respond, the negative feedback stabilises it. No scaling needed, and works whatever the calculation between the controllers.
- **Mutual adaptation**: adding feedback adapts the forward loop to unmeasured process changes; adding feedforward adapts the feedback loop to process *gain* variation. In the heat exchanger, the feedback loop sees T* − Ti via subtraction (linear, no gain change) and Wp via multiplication (nonlinear), so feedback gain varies directly with flow — exactly the compensation the process needs. **Achieve that adaptation only by feeding feedback into the set-point calculation**: if the controller output sets K instead, feedback gain would vary with Wp *and* with (T* − Ti), but process gain does not vary with (T* − Ti).
- **Economic honesty**: the heat exchanger's feedback loop is 3 items; making it feedforward adds 9 (2 flow transmitters, a temperature transmitter, 2 square-root extractors, a flow controller, a summer, a multiplier, a lead-lag). Drop a load variable that rarely varies (inlet temperature, if feedback trim is present) to save a transmitter and a summer. And shortcuts fail: adding the load signal to a controller output with fixed gain over-corrects (the gain needed usually has to be adjusted by the feedback controller); differentiating the load into the controlled variable makes feedforward steady-state *and* dynamic response depend on the PID tuning, forbids nonlinear characterisation and kills mutual adaptation; omitting the secondary flow controller exposes the calculation to valve nonlinearity and varying pressure drop (acceptable only in feedforward pH control, where the equal-percentage characteristic is exploited deliberately).
- **Where feedforward is the only answer**: (1) a difficult process with disturbances arriving faster than about three loop periods — not unusual on towers, furnaces and coupled units cycling at periods over an hour; (2) variables that cannot be measured continuously, accurately or quickly enough for feedback (and where the inferential secondary variable is a poor proxy); (3) economic variables (cost, yield, debits) that are not measured at all.

## Mental Models
- **Feedback asks "am I wrong?"; feedforward asks "what does the balance say?"** The first is universal and slow; the second is fast and needs knowledge.
- **Feedforward loops are closed loops too** — they are not open-loop programming, because the load measurements close them.
- **The energy level must move before the energy rate can.** That single physical sentence is the whole need for dynamic compensation: temperature and composition cannot change without a transient in stored energy.
- **IE is area, and area is what you can compute.** Use IE = 0 to set the compensator difference and the ratio to set IAE.
- **Put feedback where it buys something**: on the set point of the forward calculation, so it corrects the most likely error and concurrently adapts loop gain to flow.

## Anti-patterns
- **Computing the ratio inside the feedback loop** — loop gain then varies with the wild flow, or the loop becomes nonlinear in its own output.
- **Omitting the cascade flow loop** so the feedforward output drives a valve directly — valve position is not an accurate representation of flow.
- **Feeding feedback into the coefficient K** rather than the set point — wrong gain adaptation, and no single trimming knob.
- **Leaving the feedback controller in automatic while evaluating dynamic compensation** — it will always equalise the integrated error promoted by any forward-loop disturbance, hiding what you are trying to measure.
- **Using lead-lag in the manual path** — the operator's move appears minutes later.
- **Setting a compensator's lead-lag ratio from the IE requirement alone** — IE fixes the difference, IAE fixes the ratio; and high ratios saturate on large steps, destroying the balance they were set for.
- **Applying PID feedback modes to a feedforward loop "for completeness"** — they contribute nothing to load response and can destabilise.

## Worked Example
**Drum-level feedforward with windup protection**: WF = Ws + (mL − 0.5)·scale, with the level controller biased at 0.5 (mid-scale). The back-calculated feedback path fL = 0.5 + (WF − Ws)/K means that with zero flow deviation the level controller integrates normally, and with any flow deviation it becomes proportional — so a feedwater flow failure cannot wind the level controller up. The two payoff statements are explicit and generalisable: feedwater flow never changes faster or farther than steam flow, and level control stops depending on tight feedback tuning.
