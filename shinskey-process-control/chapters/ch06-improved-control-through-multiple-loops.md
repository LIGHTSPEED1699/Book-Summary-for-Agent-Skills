# Chapter 6: Improved Control through Multiple Loops

## Core Idea
One manipulated variable can only have one independent set point — but it can serve several *controlled* variables as long as their combination has one degree of freedom. That single constraint generates the whole family: **cascade** (the manipulated variable drives an inner loop, so the outer controller never sees the inner process's phase lag or gain variation), **multiple-output** (several actuators with the same effect on one variable, coordinated), **selective** (one actuator logically assigned to whichever variable is nearest its limit), and **adaptive** (the controller's own parameters follow the process). The common currency is phase: every one of these schemes is bought with knowledge of where the phase lag sits, and the chapter's central warning is that putting the lag in the wrong place — or closing a secondary loop whose resonant peak lands on the primary period — makes things worse than a single loop.

## Frameworks Introduced
- **Cascade structure**: primary controller's output becomes the secondary's set point; only the primary has an independent set point, only the secondary touches the process. Four gains: secondary-loop disturbances are corrected before reaching the primary; the secondary loop *reduces phase lag* of that part of the process; gain variation in the secondary part is absorbed inside its own loop; mass/energy flow is manipulated exactly. Close a loop around an integrator whenever practicable (to kill the inherent 90°), and use flow as the secondary variable when line pressure must not disturb the primary.
- **The closed inner loop as a process element**: its set-point gain is **dc₂/dr₂ = K_p g_p K_c g_c/(1 + K_p g_p K_c g_c)** (6.1) — steady-state gain normally 1.0 (there is an integrator in either the process or the controller). Evaluate it as a vector at the primary's period: |K_G| = K_pG_pK_cG_c, φ = φ_p + φ_c, then factor into x = |K_G|cos φ, y = |K_G|sin φ, giving G_den = √[(1+x)² + y²] and φ_den = tan⁻¹(−y/(1+x)) — **with a 180° correction when x < −1**, or the phase silently lands in the wrong quadrant.
- **The resonant peak is the trap** (Figs. 6.3–6.4): closing a secondary loop around an integrating process with a proportional controller cuts both gain and phase at long periods (at 4× the dead time phase drops; at 13×, gain does too) — this is the justification for closing the loop around a motorised valve. But the set-point gain curve peaks at **3–5 secondary dead times**, and in that band cascading is counterproductive: the primary then needs a *wider* band than without cascade. Adding integral action to the secondary raises that peak (and widens it), so integral action in a secondary controller can degrade the primary loop — avoid it where possible. A secondary controller with proportional action on the controlled variable only has a suppressed gain below unity but substantially more phase lag at all periods (it is equivalent to lagging the set point by I).
- **Secondary offset only matters if it eats range**: with a very wide secondary band (a flow loop), offset can be large enough that the primary cannot drive it full scale; and secondary-loop load changes are not fully countered without integral action.
- **External feedback (windup protection across a cascade)**: feed the *secondary controlled variable* back to the primary's integral mode instead of the primary's own output (Fig. 6.5). With no secondary deviation the primary integrates normally; with one, the positive-feedback path opens, the primary degrades to proportional, and a steady secondary offset develops as **e₂ = −(100/P)e₁** (6.3). Consequences: feeding back r₂ gives **zero IE** (the secondary eventually corrects, and the primary deviation integrated on the way out must be integrated back); feeding back c₂ gives **22% lower IAE** because the integral mode is dynamically misdirected — it integrates in the direction that reduces secondary deviation. Dropping primary integral action entirely gives the best secondary-disturbance IAE (35% of single-loop) but leaves offset on primary disturbances; that is a decision, not a default.
- **Tuning order and division of dead time**: tune the secondary first with the primary in manual; use load-response tuning if secondary load changes are expected, else set-point steps. With equal dead time split between loops (Table 6.1): no cascade → P 108, I 1.57τd, D 0.58τd, period 3.10; **feedback r₂** → 110 / 1.50 / 0.55, period 2.55, secondary-upset IAE 1.19; **feedback c₂** → 85 / 1.30 / 0.55, period 2.45, IAE 0.93; **no primary integral** → 140 / — / 0.55, period 2.25, IAE 0.72. Secondary controller in all cases **P = 110K_p, I = 0.47τd** (quarter-amplitude decay rather than dead-beat — deliberately, because it shortens the primary period; the dead-beat setting 265K_p reduces loop gain but the primary band must then be raised 10% with I and D cut up to 25%, reducing IAE by ~35%).
- **Second-loop symmetries to watch**: the primary loop is also inside the secondary, so a lightly damped secondary with the primary open can go undamped once the primary closes — chiefly through primary derivative action, whose gain changes rapidly in the τ0/D = 0.5–2 region. If secondary dead time is half the primary's or less, raising the primary band and cutting its D fixes it. If secondary dead time *exceeds* primary dead time the two periods merge: flatten the secondary's resonant peak by widening its band. In a cycling cascade, if the period is too short to belong to the primary, widen the **secondary** band first.
- **Programmed vs calculated multiple-output**: options per the process. Use a **fast integrating inner loop** over the weighted sum of all outputs when actuator effects are uniform (1 s pneumatic, less electronic, one sample digital) — manual adjustments, limits and shutdowns are then absorbed without disturbing the common variable, and the inner loop's time constant is set for the all-units-on case. With many parallel units, replace the integrating loop with a **calculation**: m_i = b_i + (n·m − Σb_e − Σm_d)/n_e (6.5) where the sums cover enabled and disabled outputs — loop gain is then always correct for the number of units in automatic, and biasing a station is instantaneously balanced by the others. While a station is in manual, continuously solve 6.5 for b_i so transfer back is bumpless; feed total output back to the master's integral mode so it cannot wind up when all units are manual or limited.
- **Selective control, four applications**: equipment protection, auctioneering (highest of many inputs — e.g. peak temperature in a fixed-bed reactor, which moves as the catalyst ages), redundant instrumentation, and variable structuring.
- **Windup protection in a selective system**: feed the **selector output** back as the common feedback to every controller. The selected controller then has its own output in feedback (integral action intact); the others get someone else's output, so they degenerate to proportional. Transfer between controllers necessarily happens **when the outputs are equal and the incoming controller's error crosses zero** — which is what makes it bumpless. With derivative on the input, e − D·dc/dt must be zero, allowing transfer before zero error and avoiding the overshoot.
- **Variable structuring (the condenser problem)**: when a constraint is reached, a controller must move to a different valve. In the condenser example, pressure normally controls reflux (via flooding level); when noncondensables accumulate and the condenser empties, level takes over reflux and pressure must move to the **vent valve**, via m_v = K(m_p − m_l) (6.12). The pressure controller stays closed throughout (so it needs no external feedback) and should be tuned while manipulating reflux; the level controller does need external feedback. The "simpler" alternative of two independent loops (PC on reflux, LC on vent) is much less effective — the level loop is then nested inside the pressure loop and its settings become dependent on the PC's.

## Key Concepts
- **Valve positioner = a high-gain proportional loop around a single capacity plus dead band and velocity limit.** It removes dead-band phase shift from the primary loop, overcomes friction and high seat pressure drop (it will put full motor force on the stem), and decouples actuator capacity from its transmission line. It is **unhelpful on flow and liquid-pressure loops**: those are self-regulating (hence stable with dead band) and the positioner raises valve gain 2× or more exactly in the 0.5–2 s band where those loops cycle, forcing a doubling of an already wide band.
- **Cascade flow loop caveats**: a differential-pressure meter in the secondary puts its square-law nonlinearity into the primary loop *inverted* — h = kF², dF/dh = 1/(2kF) (6.4) — so loop gain varies inversely with flow and can approach infinity; the loop limit-cycles around zero flow. Fit a square-root extractor. Also, enclosing a valve in a flow loop destroys an equal-percentage characteristic that may have been compensating variable dead time. And never cascade one flow controller onto another, nor a pressure controller onto flow: if the primary period approaches the secondary period, instability follows (this is the same resonant-peak effect).
- **Temperature-on-temperature cascade**: for reactors, cascade to **coolant outlet** temperature, not inlet. Outlet encloses the jacket and reacts to heat-transfer rate: the secondary band can be only 10% (vs 25% for inlet), the primary band must be twice as wide, but the primary period is much shorter, I and D shrink accordingly, and **IAE is 30% lower** (Fig. 6.8). Secondary integral action is not needed for its own sake but is required to avoid primary offset once primary integral feedback is taken from c₂, and then **its integral time should equal the primary's**. Derivative is useful if it acts on the controlled variable alone. Cascading removes the coolant-flow nonlinearity (3.60) from the primary loop entirely.
- **Modulating + on-off units in parallel**: master demand drives the on-off devices at thresholds, with a relay feedback that repositions the modulating unit back to low speed when a unit starts, so the process sees no step. A rotating sequencer evens out duty between on-off units (first started = first stopped).
- **Keeping valves open (energy saving with one surplus degree of freedom)**: select the highest flow-controller output to set pump speed, and let a slow integrating valve-position controller keep the most-open valve at ~90%. Trade-off, stated plainly: holding position constant makes valve gain vary **directly with flow** (F/m form, 6.6–6.8), which manufactures an equal-percentage characteristic out of a linear valve — bad for flow control, accepted to save energy. Compensate by putting √Δp in the denominator of a divider on each flow controller's output; sending pump speed instead is an approximation (head ∝ speed²) that is measurably less accurate and leaves the flow loops coupled. The compensation also speeds the system by closing the VPC loop without going through the flow controllers.
- **Selection with digital algorithms is positional-only.** Comparing *incremental* outputs is not equivalent and fails two ways: (1) if the selector samples faster than a controller is processed it sees Δm = 0 as false information, so the loop responds differently upscale and downscale (drives downscale at the shortest sample interval, upscale at the longest — reversed for a high selector); (2) noise is **rectified** — the selector passes Δm of one sign and rejects the other, driving the valve in the preferred direction. Equilibrium offset from noise rectification follows from 4.48: ε ≈ (Δc/2)[1 + D/I] (6.11), reducible by smaller I and D, a longer sample interval, or filtering — but it remains a fundamental defect.
- **A selective loop can end up with no controller in charge**: in the compressor example, if suction pressure falls far enough, both discharge pressure and flow sit below set point and the motor runs to full speed with both controllers saturated; on recovery both can overshoot. If that is common, insert a batch unit in the common feedback at the selector output. A controller whose output passes through a limiter can also wind up unless its integral feedback is taken downstream of the limits.
- **Adaptive control, two unrelated families**: *dynamic* adaptation targets an objective function of the controlled variable (damping, decay ratio, overshoot, IE, IAE, or minimum manipulation) — because damping identifies dynamic loop gain. *Steady-state* adaptation targets the process's steady-state gain. Both can be **programmed** (settings adjusted from measurable causes, which requires deep process knowledge) or **self-adaptive** (settings manipulated from the measured objective, which requires little knowledge but lags reality).
- **Programmed adaptation, worked form**: for the flow-variable heat exchanger, set P = P′/f, I = I′/f, D = D′/f (6.13) with f the normalized flow — one tuning at full flow then yields optimum response at every flow. Universal in digital controllers, rarely used; the obstacle is process understanding, not hardware. This is feedforward adaptation.
- **EXACT self-tuning** (the commercial pattern): pattern recognition on naturally occurring disturbances — first peak, second a half cycle later, third another; period estimated twice, I set from the longer estimate and D from the shorter; decay ratio = (peaks 2→3)/(peaks 1→2); overshoot (set-point changes) = peak 2/peak 1. A wait timer declares the loop overdamped when peaks do not appear and narrows P. Noise threshold and wait timer must be set manually or from a one-shot open-loop test.
- **Frequency-band adaptation**: split the deviation into low- and high-frequency channels with k_L setting the target ratio; if the high band dominates, loop gain is too high; if the low band dominates, too low. The integrator drives loop gain accordingly. Filter sizing: **τ_a ≈ 0.5τn** to put ~70% of the natural cycle in the high channel (6.14). Practical results on a real pH loop: k_L = 1.0 caused *burst cycling* (the adaptive loop itself going unstable); k_L = 0.2 caused a very slow cycle worse than the original; **k_L = 0.5–0.7 was stable**. Adaptor integral time at or somewhat above the controller's. Commission it by setting the band for the lowest-gain titration curve with the low-gain zone width at zero, then setting zone gain for the highest-gain curve.
- **Self-tuning limits, stated bluntly**: it manipulates linear functions only, so it cannot track a changing **titration curve shape** — a linear self-tuner adjusts for damping at set point and then goes unstable when an upset pushes pH onto a bend; five adaptive controllers compared on pH, all linear, performed equivalently. It cannot fix a **dead-band limit cycle** (widening P makes that worse) and should recognize and stop. A **cyclic disturbance** makes it reduce gain and grow the cycle, unless the disturbance period is much longer than the loop's (setting EXACT's wait timer to a quarter cycle gives the correct reaction). It cannot fix **control-loop interaction** from wrong valve assignments (Chap. 8). And on a flow-varying process it is always at least one step behind, because self-adaptation is a feedback loop around a feedback loop.
- **Self-optimizing control**: keep the manipulated variable where the process steady-state gain equals a specified K_r. K_p cannot be measured, only inferred by correlating input and output: D·dc/dt = K_p g_p D·dm/dt (6.16–6.18), which requires a **process model to phase numerator and denominator**, identical time constants on both differentiators, and limited-gain differentiation. The system has a nebulous steady state (if nothing changes, K_p is indeterminate and the divider gain is maximal, so perturbations are amplified and the loop stays in motion). Works only on fast processes (blending, fuel-air ratio). At a rounded maximum the falling process gain partly offsets the divider's rise; at a **sharp vertex** (flame temperature vs fuel-air ratio) or a composition/phase minimum that looks like a crevasse, the extreme gain produces a limit cycle that cannot be damped — only its amplitude is set by controller gain.
- **Optimization is usually not worth it**: profiles are flat, constraints bind (the economic optimum often lies outside a valve's range or the product spec), and it is fruitless to optimize the set point of a variable that is not regulated well in the first place. The model gets optimized, not the process.

## Mental Models
- **Cascade buys performance by relocating phase lag, not by removing it.** Ask where the lag lives before adding a loop; if most of it is in the secondary, the resonant peak will cost you more than you gain.
- **The asymmetries are the design**: primary inside secondary, secondary inside primary; each loop is an element of the other. That is why transfer, windup and tuning order all have non-obvious answers.
- **A constraint is a controller waiting to happen.** Selective control is just "the squeaky wheel gets the grease" made explicit, with the selector output serving as the shared feedback that keeps every unselected controller honest.
- **Programmed adaptation needs knowledge; self-adaptation needs time.** The controller with the process knowledge built in is faster, more accurate and more reliable — the self-tuner's virtue is only that it can start with none.
- **Beware the loop that adapts fast enough to oscillate**: the adaptive loop is a control loop too, and burst cycling is its limit cycle.

## Anti-patterns
- **Cascading when most of the dynamic difficulty sits in the secondary loop** — the resonant peak at 3–5 secondary dead times demands a *wider* primary band than no cascade at all.
- **Leaving integral action in a secondary controller "for safety"** — it raises and widens the resonant peak and can degrade the primary loop; and when primary integral feedback comes from c₂, the secondary's I must match the primary's.
- **Using a positioner on a flow or liquid-pressure loop** — 2× valve gain exactly where those loops cycle.
- **Cascading flow onto flow, or pressure onto flow** — equal periods, guaranteed interaction.
- **Comparing incremental (velocity) algorithm outputs in a selector** — false zeros on unsynchronised sample intervals, and noise rectification that drives the valve one way.
- **Optimizing a set point before the regulatory loops work**, or optimizing a variable that cannot be regulated.
- **Expecting a self-tuner to fix dead band, loop interaction, or a changing nonlinear curve shape.**

## Worked Example
**Coolant outlet vs inlet temperature cascade on an exothermic reactor** (Fig. 6.8): both secondaries are proportional-only. Inlet-temperature control needs P = 25%, outlet needs P = 10% — but the primary controller must then run a band twice as wide with outlet as the secondary variable. The trade is worth it: the primary period falls far enough that I and D can be cut proportionally, and the total IAE comes out **30% lower**. The lesson generalizes — judge a cascade by the resulting *primary* period and IAE, never by the secondary's apparent tightness.
